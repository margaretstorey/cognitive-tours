# Reading and Sharing Tours

How a tour moves from a sequence of waypoints to a flowing document you can share. Three stops: tours as the foundation, docent mode as the narrative layer, and the markdown view as the reading and export surface.

*5 stops*

---

## Stop 1: Tours

Tours are ordered sequences of waypoints. Docent mode adds a narrative field to each stop so the tour can guide the reader between waypoints.

A tour can represent any ordered narrative: onboarding, a prioritized backlog, a sprint, or a roadmap. It supports navigation across waypoints to tell the story.

Originated in TagSEA Routes (2006) and the Tours Eclipse plugin

`app/lib/types.ts`

> A tour is an ordered sequence of waypoints — a path through the understanding map. But a list of stops alone doesn't guide a reader. The next two features address that gap: one adds voice, one adds a reading surface. [written by Claude]

## Stop 3: Markdown view for Tours

When a tour is active, the user can toggle the left panel from the graph to a live-rendered markdown document showing the tour title, description, and each waypoint stop in sequence (with docent narratives as blockquotes). A separate Export button downloads a dated .md snapshot for archiving in the tours/ folder.

> The markdown view renders the full tour — title, description, each waypoint, and its docent narrative — as a flowing document. The Export button downloads a dated snapshot to the tours/ folder, where it lives in the repo as a versioned record of understanding at a point in time.

---

## Stop 4: TourMarkdownView

Read-only client component that renders an active tour as flowing prose. Shows the tour title as H1, description as intro paragraph, then each waypoint stop in sequence — label as H2, description, notes, filePath as inline code, and docent narrative as an amber blockquote. Scrollable. No edit controls. [written by claude]

`app/components/TourMarkdownView.tsx`

> This is the component that renders the reading experience. It takes the active tour and waypoints as props and produces styled prose JSX — no markdown parser needed, since we own the data structure. Scrollable, read-only, and earns every element it shows. [written by Claude]

---

## Stop 5: tour-markdown.ts

Pure utility module with two exported functions. tourSlug(name) converts a tour name to a URL/filename-safe slug (lowercase, hyphens, strips non-alphanumeric). generateTourMarkdown(tour, waypoints) produces the full markdown export string for a tour — used by the Export button in TourBar to generate the browser Blob download. [written by claude]

`app/lib/tour-markdown.ts`

> The utility layer underneath TourMarkdownView. Two pure functions: one that slugifies a tour name for use in filenames, one that generates the full markdown string for export. Keeping this separate from the component means the export logic can be used independently — and tested independently when Playwright tests arrive.
