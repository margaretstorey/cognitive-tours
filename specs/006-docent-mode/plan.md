# Implementation Plan: Docent Mode — Per-Step Tour Narrative

**Branch**: `006-docent-mode` | **Date**: 2026-06-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/006-docent-mode/spec.md`

## Summary

Add an optional per-stop narrative field to tours so that tour authors can write guided transition text for each waypoint stop, and readers see that text below the tour bar as they step through. The implementation has two parts: (1) a database schema addition (`narrative String?` on `TourWaypoint`) and corresponding TypeScript type change (`Tour.waypointIds → Tour.stops: TourStop[]`), and (2) UI changes in the tour editor (textarea per stop) and reader view (conditional narrative display below the tour bar).

## Technical Context

**Language/Version**: TypeScript (strict mode)

**Primary Dependencies**: Next.js App Router, React, Tailwind CSS, Prisma, better-sqlite3 (dev), @prisma/adapter-libsql + Turso (production)

**Storage**: SQLite locally / Turso (LibSQL) in production. Schema change applied via `prisma db push` in both environments.

**Testing**: No automated tests exist yet for this project. Manual verification in the running browser is the acceptance gate.

**Target Platform**: Web app, deployed on Vercel.

**Performance Goals**: Single-user; no specific perf targets beyond "narrative display updates instantly on Prev/Next."

**Constraints**: Narrative data is already loaded with the tour on page load — no additional round-trips. Display must not reserve space when narrative is absent.

**Scale/Scope**: ~30 waypoints, ~4 tours in the seeded dataset. Small scale; no pagination concerns.

## Implementation Phases

### Phase A — Schema and Types (no UI change; app compiles and runs after each step)

**A1 — Prisma schema**: Add `narrative String?` to `TourWaypoint`. Run `prisma db push` locally (and separately against Turso using production env vars). Regenerate Prisma client.

**A2 — TypeScript types**: In `app/lib/types.ts`:
- Add `export interface TourStop { waypointId: string; narrative?: string; }`
- Change `Tour.waypointIds: string[]` → `Tour.stops: TourStop[]`

**A3 — Mapper**: In `app/lib/db-mappers.ts`, update `toTour()` to produce `stops: TourStop[]` from the sorted `TourWaypoint` rows, mapping `tw.narrative ?? undefined` per stop.

**A4 — Fix type errors — mock data and seed**: 
- `app/lib/mock-data.ts`: Update `INITIAL_TOURS` — each tour replaces `waypointIds: string[]` with `stops: TourStop[]` (narrative left undefined for all seed stops).
- `app/api/data/route.ts`: Update the seed loop's `waypoints.create` call — now maps `t.stops` instead of `t.waypointIds`.

**A5 — Fix type errors — API routes**:
- `app/api/tours/route.ts` (POST): Read `body.stops` instead of `body.waypointIds`. Map to `{ waypointId, order, narrative: s.narrative?.trim() || null }` in the `create` call.
- `app/api/tours/[id]/route.ts` (PUT): When `body.stops !== undefined`, delete existing `TourWaypoint` rows and recreate from `body.stops`. Normalize empty narrative to null.

**A6 — Fix type errors — CognitiveToursApp.tsx**: Update all call sites that reference `tour.waypointIds`:
- `activeTourLength`: `activeTour?.stops.length`
- `selectTour`: `tour?.stops[0]?.waypointId`
- `onNext` / `onPrev`: index into `activeTour.stops[n].waypointId`
- `deleteWaypoint`: filter by `t.stops.some(s => s.waypointId === id)` and map to `t.stops.filter(s => s.waypointId !== id)`
- API bodies sent to PUT `/api/tours/[id]`: `{ stops: t.stops.filter(...) }` replacing `{ waypointIds: ... }`
- `WaypointGraph` prop `activeTourWaypointIds`: `activeTour?.stops.map(s => s.waypointId) ?? []`

At the end of Phase A, the app compiles and all existing functionality works — no narrative is displayed yet but the schema and types are correct.

### Phase B — Editor: narrative text areas in TourBar

**B1**: In `TourBar.tsx`, change `TourEditorState.waypointIds: string[]` to `stops: TourStop[]`. Update all internal editor helpers (`addWaypointToTour`, `removeWaypointFromTour`, `moveWaypoint`, `openCreate`, `openEdit`, `saveEditor`) to operate on `stops: TourStop[]`.

**B2**: In the editor modal's waypoint list (`editor.stops.map(...)`), add a `<textarea>` below each stop's label row:
- `placeholder="Narrative for this stop (optional)"`
- `value={stop.narrative ?? ''}`
- `onChange` updates `stops[idx].narrative`
- Rows: 2; Tailwind: `text-sm border border-gray-200 rounded px-2 py-1 mt-1 w-full resize-none`

**B3**: In `openEdit`, populate `stops` from `tour.stops` (already a `TourStop[]`).

At the end of Phase B, authors can write and save narrative. Readers don't see it yet.

### Phase C — Reader: narrative display below tour bar

**C1**: In `CognitiveToursApp.tsx`, compute the current narrative:
```typescript
const currentNarrative = activeTour?.stops[activeTourStep]?.narrative?.trim() ?? '';
```

**C2**: Render the narrative area conditionally, immediately below the `<TourBar .../>` element and above the `<div className="flex flex-1 ...">`:
```tsx
{currentNarrative && (
  <div className="bg-amber-50 border-l-4 border-amber-400 text-sm text-amber-900 px-4 py-2 shrink-0">
    {currentNarrative}
  </div>
)}
```

At the end of Phase C, the full feature is complete. Narrative shows below the tour bar when present, disappears when absent.
